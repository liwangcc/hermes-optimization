# 投稿前审阅：先发 Issue，再等维护者回应

以下都只是本地草稿，**没有发 Issue、PR 或推送候选分支**。

| 草稿 | 中文审阅摘要 | 先问什么 |
|---|---|---|
| [A：分层记忆容量](issues/A-capacity.md) | 界面分别显示 `USER.md`、`MEMORY.md` 的写入上限和事实库实报用量；不新增路由。只读体检、目录提示、提醒是后续，不绑在首个 PR。 | 能否先审独立的容量 PR3？ |
| [B：提供者的一键任务](issues/B-provider-jobs.md) | 插件列出任务和进度，由 Desktop/CLI 启动。核心不管嵌入模型或存储策略。旧的对话后回填证据与新的 Desktop 验收分别标注。 | 能否审独立的 PR7？ |
| [C：Holographic 设置面板](issues/C-holographic-settings.md) | 先让目录里的 Holographic 在已有面板配置嵌入模型；用量、体检、任务都是后续可选，不要求任何一边一起合并。 | 维护者愿意接 HOLO-1，还是希望自己实现？ |

先征询方向。明确愿意审某个独立切片后，再按反馈起对应 PR；愿意看不等于承诺合并，沉默也不算同意。每份 PR 带自己的完整结果、复现命令与限制。候选的本地证据见 [验证说明](validation/EVIDENCE.md)；后续投稿仍要用届时 `main` 验该独立补丁。

**发之前再做：**核对维护者当前已有议题/功能；确认用户批准该正文和目标；三份 Issue 稿不带未发布的适配器链接，只有用户批准公开且能验证固定 SHA 可访问才补；跨库 ID 仅用已经存在的 Issue/PR；不上传原始日志、私有评测数据或本机配置。
