# 召回时只把关键词提供的新措辞当作补充证据

2026-11-22。推荐比较项是 `novel_terms`。在与原插件逐题配对的 1,770 行中，前五至少有一个正确事实的命中由 772/848 提高到 776/848。新增的 4 条事实都是答案。没有原有目标跌出前五。真实库由 34/44 提高到 35/44。CPU 实验使用一个驻留的 bge-m3，查询向量只计算一次。

922 道无答案题中，返回过事实的有 566 道，两臂相同。有答案题中，前五带有任意非目标的有 321 道，两臂相同。另把两份小库中每道有答案题的全部标注目标从临时数据库删除，用原问题重跑词法、实体、向量和门槛。真实库 44 题的噪声行是 34 → 34，合成库 36 题是 13 → 13，两库都没有新增错误事实。这 80 行另计。移除标注目标的压力测试以原标注穷尽了可答事实为前提。

household 新增目标来自英语 `q064` 和中文 `q033`，是两个不同题号。全部四题救回、零题丢失，即使把所有行视作独立，精确双侧 McNemar 也只有 p=0.125。真实库里的一题相当于 2.27 个百分点。与以前的双档 z 规则相比，两份小库的命中增量打平，都是各救回一题。规则选择用过真实小库、合成小库和上游题，适合把这些数字作为开发样本的实测增益。

### 迁移检查

SQuAD 2.0 的评测单位为一条能放进插件展示上限的段落摘录。每个主题一条，正例的标注答案必须在摘录内。负例为原段落的无答案题。其他文章可能含有通用答案，统计沿用数据集的段落标注。所有文章和测试题号在四组间互斥。

| 来源与取样 | 事实 | 有答案 / 无答案 | 基线 → 方案命中 | 新增错误事实 |
|---|---:|---:|---:|---:|
| 官方 dev | 35 | 68 / 105 | 67 → 67 | 0 |
| 官方 train，第一组 | 50 | 101 / 150 | 99 → 99 | 0 |
| 官方 train，第二组 | 50 | 103 / 150 | 99 → 99 | 0 |
| 官方 train，另 50 篇，预留确认 | 50 | 72 / 149 | 70 → 70 | 0 |

前三组的关键词由原文稀有词生成。每组只有一条事实在归一化后拥有正文以外的词，适合检查重复计分。最后一组在规则冻结后才运行。每篇另取一条有标注的问题给事实写关键词，再把该问题及其同文版本从评测中排除。50 条事实中有 36 条带有正文以外的措辞。这批独立题上观察到零误加，也观察到零救回。前三组在选最终规则的过程中用过。[SQuAD 2.0 数据](https://rajpurkar.github.io/SQuAD-explorer/)

## 实际决策

1. 执行原插件的 `prefetch`。前五有空位时，用同一个问题向量分别搜索“原句＋关键词”和“仅关键词”两个预建索引。两路的唯一第一名须为同一事实。已经展示的 ID 直接结束本次补召。
2. 检查候选的关键词是否提供了用户这一次实际用到的新措辞。将问题、关键词和事实正文作相同的 Unicode 归一化。英文等按词，连续汉字按相邻二字切分。问题至少有一个词出现在这条事实的关键词中，且没有出现在它的正文中。例如正文为“清理临时产物”，关键词为“编译缓存”，问“编译缓存在哪”就有了额外证据。
3. 设 N 为已建向量的事实数，B 为 sqrt(2 ln N)。每一路将第一名分数与其余事实的均值和总体标准差比较。已有结果时，两路标准分都须达到 B+1。原本静默时，原句加关键词的一路须达到 B，关键词一路须达到 B+2；问题还须带问句线索，候选的最佳关键词词法分须唯一领先，且至少是第二个事实的 1.5 倍。词法分是同一条关键词中匹配词的 IDF 之和除以该关键词总 IDF 的平方根。并列、背景方差过小或没有新证据时不追加。
4. 仅对胜者再次应用原插件的信任、姓名、可展示及近期重复检查，然后在原有顺序末尾追加一条。原插件继续处理 token 预算和回执。实验使用新会话及默认不限 token 预算，多轮连续使用、事实持续更新及大库负载尚待实测。

两个索引额外存储每条事实的向量。1024 维 float32 约为每条事实增加 8 KiB，另有关键词倒排表。查询阶段只调用现有编码器一次。实验包也计算了按事实的 95% 背景分位数，供较宽的对照使用；推荐规则只用本轮竞争者的均值、标准差和关键词匹配。

## 哪些做法增加了污染

| 单轮规则 | 救回有答案题 | 新增错误事实 | 新增噪声行 |
|---|---:|---:|---:|
| 关键词须命中正文以外的措辞，并由两路共同确认 | 4 | 0 | 0 |
| 同样的两路门槛，取消新措辞条件 | 5 | 3 | 2 |
| 已经有结果时才由两路确认 | 2 | 1 | 0 |
| 已有结果走两路确认，静默时用词法和背景分位数放宽 | 8 | 8 | 7 |

新增错误事实按条计，包括加在原来就混有错项的行。只看净噪声行和净混淆行会掩盖这种注入。单独把真实库词法候选池从 15 扩到 30 并将覆盖门槛从 0.30 降到 0.25，命中由 34 升至 36，同时新增 22 条非答案，混淆行由 30 增至 34。

还有一种范围较窄的纯提升。重跑上游已有的 `prefetch_clause_coverage`，16 道俄语双问题中，两问的答案同时进前五由 12 道增至 15 道。整个 650 行配对回放里，新增非目标、目标丢失和新增噪声均为 0，另 620 行的结果逐行相同。该开关识别英语和俄语问句，使用词法检索，测试时向量和重排均关闭。其指标是双问答全率，独立于上表的单题命中率。[上游设计与 5,081 条真实消息的记录](../../vendor/holographic-0.30.0/docs/two-topics.md)

## 速度与使用条件

真实库 54 个问题逐个调用，Intel Core i7-12650H，4 个 PyTorch 线程，强制 CPU。计时从原插件接收问题到返回结果，包含本机分词和编码、SQLite 检索、向量搜索、过滤和组装。实验走进程内调用。54/54 个单问实时编码的输出与预编码批量回放逐项相同。

| 路径 | P50 | P95 | 最慢 | 超过 3 秒 |
|---|---:|---:|---:|---:|
| 基线，模型驻留 | 109 ms | 138 ms | 148 ms | 0/54 |
| 推荐规则，模型驻留 | 128 ms | 159 ms | 203 ms | 0/54 |
| 只走已就绪的 SQLite 词法与实体 | 10 ms | 22 ms | 24 ms | 0/54 |

该次模型准备需 10.71 秒，三种事实向量及对照用的背景分位数准备需 116.43 秒。因此交互使用依赖预加载、在写入或后台构建索引。模型或索引未就绪时可直接走词法与实体，本次实测该路径命中 31/44。结果来自本地实验接入，未部署到生产侧车或测量远程调用、并发排队延迟。

## 复现

使用 Python 3.11、NumPy 1.26.4、PyTorch 2.11.0、Transformers 5.8.1、sentence-transformers 5.5.0、snowballstemmer 3.1.1。模型是 BAAI/bge-m3 的本机 PyTorch 权重，权重 SHA-256 为 `b5e0ce3470abf5ef3831aa1bd5553b486803e83251590ab7ff35a117cf6aad38`。自有小库使用插件 0.27.0，上游与 SQuAD 使用 0.30.0。配对两臂使用同一副本、事实、关键词、模型和插件，基线用原句向量，两臂的词法部分都能看到关键词。上游公开的 770 行使用本轮在 CPU 计算的向量和原插件逐题执行；逐句比较与上游历史的 481/525 属于不同的模型、配置和题池。

从项目根目录运行。示例中的 `$ModelDir` 是本地 bge-m3 路径，`$CoreDir` 是提交 `e8a31a1` 中的 `memory/keyword-gate/core_shim`。真实数据传冻结数据库副本和同次标注文件。程序输出汇总计数，模型加载仅使用本地文件。

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$Eval='memory/threshold-calib/calib_consensus.py'
$Small='vendor/holographic-0.27.0'
$Public='vendor/holographic-0.30.0'
python -E -B $Eval --suite synthetic --model $ModelDir --core-src $CoreDir --plugin-src $Small --mask-targets
python -E -B $Eval --suite real --store $StoreCopy --queries $Queries --model $ModelDir --core-src $CoreDir --plugin-src $Small --benchmark --mask-targets
python -E -B $Eval --suite household --lang en --model $ModelDir --core-src $CoreDir --plugin-src $Public
python -E -B $Eval --suite squad --squad $SquadTrain --article-offset 100 --support-keywords --model $ModelDir --core-src $CoreDir --plugin-src $Public
python -E -B -m pytest -q memory/threshold-calib/tests
```

`household` 另跑 zh、ru。`contrast_en`、`contrast_zh`、`contrast_ru` 各跑一次。`multi` 分别跑 de、en、it、ja、nl、ru、th、zh。`squad` 其余三组使用官方 dev、官方 train、官方 train 加 `--article-offset 50`。三个命令均沿用程序默认的正文关键词；完整明细按数据集、语种和拆分保存在 JSON 中。[官方 dev JSON](https://rajpurkar.github.io/SQuAD-explorer/dataset/dev-v2.0.json) · [官方 train JSON](https://rajpurkar.github.io/SQuAD-explorer/dataset/train-v2.0.json) · [逐集合计数](consensus-results.json)
