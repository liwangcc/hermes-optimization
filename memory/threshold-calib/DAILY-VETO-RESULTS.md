# 用同一个查询向量隐去离题的召回事实

2026-11-22。对象是日常版 0.6.0 的本地模式。不加模型，也不多算一次向量：侧车本来就为每条消息算出了它和全部事实的余弦，这一轮用这些余弦，把块里明显离题的事实隐去。规则只在开发集上设计，冻结后在留出集上判了一次。

**结论：两条主规则 P1、P2 都按事先写死的条件判为纯增益。** 留出集 455 题（contrast 英俄中、multi 八种语言、two_topics 俄语），对比日常版 0.6.0：

- 展示的非目标 723 → 537（−26%），混淆行 173 → 144，噪声行 96 → 88。命中 264 → 264，P2 为 265。丢失目标 0，新增错误事实 0。
- 注入的事实条数少 18.5%，字符少 17%。块里目标的占比从 28% 升到 35%。
- 延迟和显存与 0.6.0 相同：GPU P95 48–77 ms，纯 CPU P95 103–126 ms，最慢 155 ms；显存约 1.26 GB。
- 加实体门槛的两条（P1E、P2E）在 multi 意大利语上丢了 1 个目标，判为换取，不要。

| 规则 | 开发集：命中 / 丢失 / 噪声 / 混淆 / 非目标 / 新增错误 | 留出集：命中 / 丢失 / 噪声 / 混淆 / 非目标 / 新增错误 | 判定 |
|---|---|---|---|
| 日常版 0.6.0 | 183 / — / 99 / 102 / 551 / — | 264 / — / 96 / 173 / 723 / — | — |
| **P1** | 183 / 0 / 84 / 81 / 404 / 0 | 264 / 0 / 88 / 144 / 537 / 0 | **纯增益** |
| **P2** | 188 / 0 / 88 / 81 / 408 / 4 | 265 / 0 / 88 / 144 / 537 / 0 | **纯增益** |
| P1E | 183 / 0 / 80 / 73 / 329 / 0 | 263 / 1 / 88 / 107 / 422 / 0 | 换取 |
| P2E | 188 / 0 / 84 / 73 / 333 / 4 | 264 / 1 / 88 / 107 / 422 / 0 | 换取 |

开发集 210 道有答案、183 道无答案；留出集 272 道有答案、183 道无答案。命中按整个注入块算，混淆行是带任意非目标的有答案题，噪声行是有输出的无答案题，非目标按条计。

## 规则

全部只用日常版已经算好的东西：基座的块和其中哪些来自词法流，以及这条消息的查询向量对 `原句 + " " + tags` 向量的余弦。没有向量的消息（问候、太短）原样输出。

- **否决**：块里的事实，余弦低于 0.35，或比基座块的最高余弦低 0.20 以上，就不显示。词法第一条只受 0.35 约束。语义追加的那条是全库余弦第一，永远不会被否决。
- **静默块撤回**：基座什么都没找到时，最近的事实还要从全库突出：标准分减 `sqrt(2 ln N)` 不低于 −0.5（N 为可信事实数），否则不追加。这一条专挡闲聊。
- **静默块补召（只在 P2）**：同样是静默块，余弦在 0.45–0.55 之间、突出度不低于 1.0、领先第二名不少于 0.02 时，也追加这一条。

P1 = 否决 + 静默块撤回。P2 = P1 + 静默块补召。

## 收益来自哪里

| 组成 | 开发集：噪声 / 混淆 / 非目标 | 留出集：噪声 / 混淆 / 非目标 |
|---|---|---|
| 日常版 0.6.0 | 99 / 102 / 551 | 96 / 173 / 723 |
| 只有否决 | 98 / 81 / 418 | 90 / 144 / 539 |
| 只有静默块撤回 | 85 / 102 / 537 | 94 / 173 / 721 |
| P1 | 84 / 81 / 404 | 88 / 144 / 537 |

- 留出集上的收益几乎全来自否决：删掉的 186 条里 184 条是否决删的。静默块撤回只触发 2 次，补召只触发 1 次（补对了）。所以留出集主要检验的是否决。
- 补召单独看是换取：开发集触发 9 次，5 对 4 错，4 条错的都落在无答案题上（例如问锅炉维护多少钱，给出「锅炉九月检查」）；留出集 1 次，补对。P2 相对 0.6.0 仍是纯增益，靠的是静默块撤回和否决省下的量。
- 删掉的事实在开发集和留出集合计 333 条，其中标注目标 0 条；而 0.6.0 展示的事实里约 28% 是目标。按三法则，被删事实是目标的概率 95% 上界约 0.9%。
- 每个留出题集都没有变差，包括泰语和日语。multi 八种语言的非目标 157 → 83，two_topics 38 → 28。

## 被删的是不是真的没用：逐条人工审计

只计标注目标的口径看不到「有用但没标注」的事实，所以另派了一个子代理，按原语言逐条读完全部被删事实：A 是答案，B 是有用的上下文，C 是无关或误导。

| | 删掉 | A 答案 | B 有用 | C 无关 |
|---|---:|---:|---:|---:|
| 留出集 | 186 | 0 | 19 | 167 |
| 开发集 | 147 | 1 | 6 | 140 |

- 留出集 19 条 B 里，14 条是同一条用户偏好「Anton 要简短回答、不用列表」，在问 Anton 的滑板车、咖啡时被删。按插件自己的写入路由，这类偏好应进 USER.md、每轮都在系统提示里，那时它在块里就是重复。另有 2 条明确有用（如问 HR24 Copilot 时删了「克修莎经营 HR24」），3 条弱相关。
- 开发集的 1 条 A：household 中文 q055「巴尔西克的喂食和打针是怎么安排的？」，被删的「索妮娅每天早上喂猫」回答了谁喂，而标注只给了另外两条。这一题仍算命中（两个标注目标都在），属于多部分问题丢了一部分没标注的答案。
- 静默块撤回的 16 条（开发集 14、留出集 2）都不是答案。留出集有一条只差 0.003（标准分 −0.503）。

审计记录在 [daily-veto/label-audit-test.json](daily-veto/label-audit-test.json) 和 [label-audit-dev.json](daily-veto/label-audit-dev.json)，每条有问题、事实、余弦、删除原因和判定。

## 原生实现和可用性

改动只在日常版插件的两个文件里，补丁是 [daily-veto/plugin.patch](daily-veto/plugin.patch)（对当前工作区可用 `git apply` 应用，见文末）：

- 侧车 `/candidates` 多收一个可选字段 `ids`，带上时多返回这些事实的余弦、全库前两名、可信事实余弦的均值和标准差。它们都来自同一次编码，只有模型 id 是 bge-m3 时才返回。
- 包装器在基座排出块、还没记成「已注入」之前做否决，所以被隐去的事实不会占用重复窗口。每轮仍只调一次侧车。语义步改用基座去掉引用、通知和署名后的那段话。

| 原生 0.6.0 对离线回放 | 848/848 |

## 没有成立或没做的

- **实体门槛**（实体流事实还要余弦 ≥ 0.55）：开发集上实体流展示了 180 条、目标 0 条，看起来是纯污染；留出集上丢了 multi 意大利语 q14 的目标（余弦 0.538）。不要。
- **只降静默块的 tau**：0.50 时多救 11 行，但多带 39 条错误事实。
- **RRF 融合、否决后补位、放宽覆盖率再按余弦重排、换别的向量视图、拿 names_fit 当否决**：在开发集上就带进大量污染或丢目标。
- **去重**：16 个题集里余弦超过 0.9 的事实只有一对，是最小对「迪娜每周二去游泳馆 / 蒂娜每周四去游泳馆」，说的是两个人。按余弦去重会删错，有 2 个块会丢目标。基座写入时已有 `near_duplicate` 检查，这些题集上拿不出去重的可验证收益。

## 和上游门禁的关系

这是日常版的改动：规则依赖日常版自己的侧车，上游 Holographic 没有侧车，补丁不能原样提给上游。上游门禁是 `tools/mcnemar_gate.py`（PR #10 定下，跑测试切分）：A 分支要求命中@5 提高 ≥5 个百分点且 McNemar p < 0.05；B 分支要求前五一个目标不丢，并且混淆严格减少；两支都要求配对齐、混淆和噪声不高于基线。改准入余量的 PR #17 四条件另外要求救回达到 p < 0.05。

用上游自己的口径在本轮数据上重算（[gatecheck.py](daily-veto/gatecheck.py)；混淆只数题集指定的干扰事实，噪声只数闲聊行）：

| 比较，bge-m3 | 命中@5 | 前五丢失 | 混淆 | 噪声 | A | B |
|---|---|---:|---|---|---|---|
| 日常版形状 P1 对 0.6.0，contrast + multi | 241 → 241 | 0 | 27 → 18 | 95 → 88 | 不过 | 过 |
| 同上，household test 切分 | 63 → 63 | 0 | 7 → 5 | 20 → 10 | 不过 | 过 |
| 只否决基座块，用上游默认的向量文本（只有原句），contrast + multi | 234 → 234 | 0 | 27 → 20 | 83 → 80 | 不过 | 过 |
| 同上，household test 切分 | 52 → 52 | 0 | 7 → 2 | 7 → 7 | 不过 | 过 |

- 只删不加的规则不可能提高命中，A 分支和 PR #17 四条件都过不了，能走的只有 B 分支（精度）。
- 本轮数据上 B 分支的条件都满足，换成只有原句的向量文本也不丢目标。
- 这还不等于能过上游门禁：上游要在自己的形状上跑（基座打开 embeddings、带官方的语义流），用上游记录所用的模型，而 0.35 和 0.20 是在 bge-m3 上定的绝对余弦，换模型不一定成立；门禁脚本也还没有这种开关的配对方式。

## 限制

1. 留出集是上游现成的题集，只有特征是冻结后才生成的。contrast 和 multi 在本项目此前做别的规则选择时用过，不是新写的题。这次的规则设计没有碰它们（三个探索子代理只读开发集，冻结早于留出集特征 1 分多钟，哈希见 [PLAN-FREEZE.sha256](daily-veto/PLAN-FREEZE.sha256)）。
2. 对只删不加的规则，判据只能看到「标注目标丢没丢」，看不到删掉的有用上下文。这一面靠上面的人工审计补；审计是一个子代理的判断，B 类带主观成分。
3. 独立样本不多：455 行只有 130 个题目模板，块里有目标的模板 71 个。按模板算，每个模板丢目标的概率 95% 上界约 4%。阈值离最近目标的余量，留出集 0.069，开发集 0.102。更紧的值（下限 0.42 / 0.45）开发集不丢、留出集丢 1 / 5 个，所以不能再往紧调。
4. 留出集的无答案题全是闲聊，没有「问了但库里没有」的题，噪声行只降了 8 行。
5. 只验证了 bge-m3。另外两个内置模型由侧车自动退回 0.6.0 行为。
6. 只验证了 rerank 关闭的路径。打开 rerank 时不做否决，静默块的两条规则仍生效，这一组合没测。
7. 语义步改用基座去掉引用后的那段话（0.6.0 用的是原消息）。题集里两者逐字相同，真实 Telegram 回复上的效果没测。
8. 真实库（54 条事实）在项目外，没有跑。

## 复现

Python 3.11.4、NumPy 1.26.4、PyTorch 2.11.0、sentence-transformers 5.5.0，bge-m3 用 `vendor/models/bge-m3`，CUDA fp16。`$Shim` 是提交 `e8a31a1` 里的 `memory/keyword-gate/core_shim`（`git archive e8a31a1 memory/keyword-gate/core_shim | tar -x -C <目录>`）；原生对照需要再把 `daily-veto/shim-extra/` 复制进去。特征转储里有题集原文，放在仓库外。

```powershell
$V = 'memory/threshold-calib/daily-veto'
python -X utf8 -B $V/recall_dump.py --suite household --lang zh --core-src $Shim --out $Out/dev
python -X utf8 -B $V/recall_dump.py --suite contrast_en --core-src $Shim --out $Out/test
python -X utf8 -B $V/recall_dump.py --suite multi --lang ja --core-src $Shim --out $Out/test
python -X utf8 -B $V/recall_dump.py --suite two_topics --lang ru --core-src $Shim --out $Out/test
python -X utf8 -B $V/report.py $Out/test
python -X utf8 -B $V/native_daily.py --suite household --lang zh --shim $ShimWithStubs --plugin-dir $PatchedCopy --server $PatchedCopy/managed_server.py --compare $Out/dev/household-zh --rule-file $V/rule_P2.py --out run.json
```

开发集另有 `synthetic` 和 household 的 `en`、`ru`；留出集另有 `contrast_ru`、`contrast_zh` 和 multi 的 de、en、it、nl、ru、th、zh。`report.py` 输出各规则的计数和判定，与 [test-results.json](daily-veto/test-results.json)、[dev-results.json](daily-veto/dev-results.json) 一致。原生对照的逐次结果在 [native-summary.json](daily-veto/native-summary.json)。故障和预算探针在 `daily-veto/probes/`，不需要模型：第一个参数是打过补丁的插件目录，第二个是一个工作目录，里面放 `daily_eval.py`、`native_daily.py`、`recall_dump.py`、带桩的 `shim/` 和转储好的 `dump/dev`、`dump/test`。

## 建议和后续

**要不要做**

- 建议做。P1 和 P2 相对 0.6.0 都是纯增益，延迟、显存不变，侧车不可用、太旧或换了模型时自动退回 0.6.0。
- P2 比 P1 多一条静默块补召，单看是换取（开发集加留出集合计 6 对 4 错）。想要「召回也涨」用 P2；不接受任何新增错误事实就用 P1，两者是同一份代码，P1 去掉补召那一个条件即可。

**要做的话改哪里**

- 日常版 `memory/plugin/holographic-semantic/__init__.py` 和 `managed_server.py`，即 [plugin.patch](daily-veto/plugin.patch)。改完 `__init__.py` 587 行，`managed_server.py` 239 行。

- 落地时还要：`memory/plugin/test_catalog.py:381` 的请求体期望加上 `"ids": []`，并补一条「侧车回答畸形时基座块不变」的用例；`config_schema.py` 和 README 里「最多补充一条事实」的说明改为也会隐去离题事实；版本号；发布说明提醒重启已运行的托管侧车（旧进程会继续讲旧协议，静默退回 0.6.0）。
