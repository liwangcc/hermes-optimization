# Holographic-Semantic 向量模型设置

打开 **设置 → 记忆与上下文 → 持久记忆 → 向量模型**。「云端 | 本地」分段控件切换要配置的模式，标题旁标明当前生效的模式。向导设置当前配置档案的记忆向量模型，新会话使用新的连接。

- **云端 → 测试并连接**。沿用 Holographic 自己的 `embedding_url`、`embedding_model`、`embedding_key_env`，默认预填 OpenAI。试连只发送固定的一句测试文本，通过后才保存地址、模型和密钥并切换到云端；失败时原连接和生效模式不变。密钥按端点匹配：为某个地址保存的密钥只会发往该地址，官方 OpenAI 地址可以留空以复用当前档案已有的 `OPENAI_API_KEY`。启用云端后，用于向量化的事实文本、相关消息和检索词会发往该服务。
- **本地 → 选择模型 → 一键部署并连接**。可选模型见下表。选中模型时显示权重下载大小、已缓存大小、缓存路径和预计所需磁盘空间（首次部署还包含运行环境）。部署先检查现有侧车：已运行的 BGE-M3 侧车（含手工管理的 CUDA 侧车）直接复用；否则在 Windows x64 的 Hermes Python 3.14 上创建独立运行环境，下载并校验权重，启动监听本机回环地址的服务。连接时校验向量维度与所选模型一致。换模型时旧的受管服务会被停止，手工管理的侧车不受影响。
- **提供方任务 → 为已有事实建立语义索引 → 运行**（在连接下面、各项设置上面）。连接完成后，用这项任务为已有事实补建本地索引。
- **相似度阈值 → 一键初始化阈值**（紧跟在连接和任务后面，不在高级设置里；所有设置都在这一页）。在当前档案的事实上校准当前生效模式的阈值：本地是 `semantic_tau`，云端是 `embedding_min_score`。任务显示当前值、建议值和依据，点击「确认写入」后才写入配置。事实少于 20 条或模型分不开相关与无关内容时，说明原因并保留原值。

| 模型 | 语言 | 维度 | 权重 |
|---|---|---|---|
| BGE-M3（默认） | 多语言 | 1024 | 约 2.14 GiB |
| BGE-small-zh v1.5 | 中文 | 512 | 约 92 MiB |
| Multilingual MiniLM-L12 v2 | 多语言，每条事实读取前 128 个 token | 384 | 约 463 MiB |

本地部署的文件位于当前配置档案下的 `services/memory-embeddings`：权重在 `model-<提交前 12 位>`，索引在 `vectors/<模型>-<提交前 12 位>`，所以索引按档案、模型和版本隔离，换模型不会混用向量。每个模型固定了提交、文件大小及 SHA-256（`local_models.py`）。Windows 运行环境锁由 `local-runtime.in` 生成，对每个安装包校验散列值。已部署的受管侧车可在下次会话开始时重新启动。现有手工管理的侧车继续由其原有启动方式管理。

## 阈值校准怎么选值

逻辑取自 `memory/threshold-calib`（`threshold_calib.py`）：从事实正文截取中间一半作为探针，四分之三保留原事实（片段，应当召回），四分之一把原事实拿掉（无答案，任何召回都算误召回），再加内置闲聊。不调 LLM，不需要标注。

1. 抽两批探针。第一批上取「无答案探针一条都不召回」的最低阈值。
2. 第二批复核这个值：片段召回不低于 80%，误召回不超过一成。两批都通过才给出建议值。
3. 本地按侧车的规则判定（余弦 ≥ 阈值，取最近的 `semantic_max_extra` 条，向量由侧车 `/embed` 生成）。云端按 Holographic 自己的 `Meaning.standout` 判定（下限叠加在默认 z 分数准入之上）；默认准入已经没有误召回时，结论是无需设置下限。

片段与原事实字面重叠，召回数字偏乐观，误召回一侧可信。校准只衡量语义通道，关键词、实体和重复窗口不在其中。

## 事实目录的标签

事实目录（`catalog_enabled`）把每条可召回事实以 `#编号=标签` 放进系统提示，给模型一张「有什么」的地图：自动召回没带出来的事实，模型看到相关标签时可以用 `fact_store get` 主动取。标签只需要让模型大概知道这条事实讲什么。

- 不超过 `catalog_label_tokens`（默认 30，一个汉字算 1）的事实，标签就是全文。
- 更长的事实用它的关键词当标签。关键词是主模型写入时给出的「别人会怎么问这条事实」的词，包含原文里没有的同义词和上位词，所以间接的说法也能联想到。
- 目录开启时，`fact_store add` / `change` 写入较长的事实必须带关键词，否则插件拒绝并提示模型带上关键词重发。短事实不受影响。
- 旧事实和不经过工具写入的事实可能没有关键词，目录里只能显示开头。**设置 → 记忆与上下文** 的事实目录一行会显示这样的条数；对 Hermes 说「给没有关键词的事实补上关键词」，它会用 Holographic 自带的 `enrich` 补齐。

## 查看和修改事实

插件不提供事实库编辑界面，写入只走 `fact_store` 一条路，这样版本历史、可信度和写入审批都保持有效。

- 想改某条事实或它的标签：直接对 Hermes 说，例如「把 #12 的关键词改成……」「#30 已经过时，删掉」。
- 想整体过一遍：用记忆复查（**设置 → 记忆与上下文 → 打开记忆复查**，或命令中心的维护页）。它列出建议的更新、合并和删除，勾选后加入聊天，由 Hermes 执行。
- 不想被复查建议删除或改动的事实，让 Hermes 给它加上 `protected` 标签。
- 不要直接编辑 `memory_store.db`。
