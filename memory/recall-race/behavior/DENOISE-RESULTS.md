## 结论先行

**用户的“查询向量筛指针，只注入相关指针”方案在降噪目标上成功。** 原 C4（cos≥0.45）在这批 116 道题上：

- catalog 平均指针数 **157.16 → 12.09（−92.3%）**；
- catalog 平均行数 token **2267.14 → 166.91（−92.6%）**；
- 非目标指针总数 **18140 → 1307（−92.8%）**；
- 真模型无答案题误取：**4/30 → 3/30**，误取事实条数 **8 → 5**；
- 漏目标正确 get：**16/43 → 30/43**，配对新增 15、丢失 1，exact McNemar p=0.000519；
- 实际 prompt token：**438385 → 124453（−71.6%）**，HTTP 请求 145 → 158。

因此，“向量筛指针没用”的旧结论撤回：它既显著减少 catalog 上下文噪声，也在这批模型行为测试中提高了补查命中。代价是结构上仍漏 6/44 个自动召回漏目标指针，且动态 catalog 不能按静态缓存价计费。

**当前最均衡候选是 top10 向量指针**：平均 10 条、143.77 line tok；漏目标 get 32/43；无答案误取 4/30（与 full30 持平）；prompt token 119178（五臂最低）。它在单库离线保留 44/44 漏目标，但大库离线只保留 43/44，尚不能称全场景无损。

**vec40+8-token 标签**补查最强（42/43），但把无答案误取推到 16/30，不能作为降噪默认。它证明“宽筛+短标签”提高可见性/触发率，同时制造更多工具探索。

## 为什么第一轮没测出来

`referee.py` 的 `noise_rows/confused_rows` 只读自动检索输出 `keys`；catalog 另算可见性与标签排名，没有把无关指针计入噪声。第一轮能证明 C4 的 token 收益和 6 个指针损失，不能证明它没有降低 catalog 噪声。本复测把两者分开。

### 答案启发式

`payload_any_hit` 是次级透明启发式，不是人工语义金标。正确 get 后命中特征词：full30 15/16、static8 39/41、vec45 29/30、vec40_lab8 41/42、top10 32/32。未 get 但答案含特征词的样本保留逐条回执，不能据此宣称记忆补查成功；可能来自问句回声、参数知识或启发式假阳性。

## 判定

1. **用户原方案通过“降 catalog 噪声”验收**：无关指针、line token、实际 prompt token 大幅下降，无答案误取不升，漏目标 get 显著提高。
2. **原 C4 不是补漏无损方案**：结构上漏 6/44；模型行为虽净增 14 个正确 get，仍有一个相对 full30 的丢失样本。
3. **top10 是当前降噪/补查最均衡候选**，但需要大库真模型复测和一个明确丢失样本的人工语义审计，才能谈生产默认。
4. **vec40_lab8 是补查优先候选，不是降噪默认**：42/43 很强，但无答案误取 16/30，工具探索明显增多。
5. **static8 只适合 token 压缩目标**：它不删除无关指针，且本轮诱发更多 get；不能拿它替代用户的筛指针方案。
