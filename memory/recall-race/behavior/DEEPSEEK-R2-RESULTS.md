# DeepSeek V4.1 Flash 1017 × 官方召回 / R2 动态指针：真模型行为结果

模型：`deepseek-v4.1-flash-1017`（请求名与全部 325 条回执返回 model 一致）  
路由：现有 qwen Token Plan，Chat Completions stream + usage  
题集：冻结合成公开 pack 的 68 题分层样本 × 2 臂 = 136 逻辑会话  
执行：并发 1、零自动重试、每会话最多 3 HTTP；实际 325 HTTP，0 HTTP/transport 错误。  
原始回执：`<HERMES_HOME>/cache/scratch/recall-race-deepseek-r2/{questions,receipts,runs,aggregate}.json*`

## 先说结论

**R2 动态指针在这个 Flash 模型上确实触发了主动补查，并显著提高最终可答率；但它不是免费降噪：仍会冗余查询、误取无关事实，且本轮总 prompt 只省约 4%，未缓存输入反而更多。**

最硬的证据是 33 道“官方全文漏目标、R2 只给指针”的题：

- 官方臂：0/33 能按 ID get（生产形状本来没有 get），最终答出目标特征 14/33。
- R2 臂：23/33 主动 get 到漏目标，其中 21/33 首轮就 get；最终答出目标特征 28/33。
- 21/33 同时满足“get 到目标 + 最终答案含目标特征”。

所以“模型看到短指针会不会去查”不再是假设：**会，而且多数时候查对。**

## 行为细节

- R2 的 33 道指针题中，10 道没有 get 到漏目标：7 道改走 search/probe 后仍答出特征，3 道三轮耗尽无答案。说明指针不是唯一补漏路径，基础 search/probe 也能救一部分。
- R2 在 10 道“官方漏、R2 已全文命中”题中，7 道仍冗余 get 已展示目标；但 10/10 最终答出特征。全文已经够时，指针/工具面仍诱发确认性查询。
- 无目标题 R2 有 2/12 发生 get，共 63 个非目标 get 条目（含多 ID 批量取）。这证明动态指针仍有注意力成本，不能把“指针不算正文噪声”理解成零行为噪声。
- 官方臂没有 #id 目录与 get，所以用 search/probe/list 自主补查；27/68 三轮后仍在查，最终答案缺失率高。R2 把其中许多探索收敛成一次 get。

## 答案准确性的边界

`payload_any_hit` 是 Unicode/CJK/西里尔兼容的目标特征词启发式，不是人工语义金标准。它可能把“提到相关词但答错”算命中，也可能漏掉同义改写。本报告把“最终给出答案”和“含目标特征”分开，并保留全部原文。严格任务正确率需要逐题人工/语义 rubric；当前数字应读作**可答率与证据使用代理**，不是最终考试分数。

## 指令样噪声坑：首轮已跑但质量聚合无效

另建 8 任务×2 臂合成噪声探针（相关约定 vs 旧笔记/个人偏好/调试便签/玩笑）。首轮 9/16 后按停止条件封存：N05 第二轮 1536 completion 全为 reasoning、可见答案空（finish=length）。

更重要的是自动 forbidden 字符串判据有缺陷：模型写“旧笔记说统一返回 XML，但已过期、不采用”会被误判采纳噪声；“不要写 config.py”也因出现 config.py 被误判。required 长短语同义改写也被误判缺失。因此首轮 task_pass/forbidden_hit **作废**，原始答案保留待语义复核。客观行为可见：模型经常明确拒绝干扰并说明其过期/非生产，但也常把干扰写进答案做排除说明；是否算“噪声影响”必须按采纳/拒绝提及区分，不能按字符串出现计。

详见 `DEEPSEEK-NOISE-FIRST-PASS-INVALID.md`。未自动重试、未扩测。
